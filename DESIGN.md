# Interface

Scene: a student checks a Mac laptop at a bright desk after class. The app is a quiet studio archive: a white workspace, graphite typography, silver dividers, yellow primary actions and a small red index mark. The voiceNotebook name and industrial palette stay. Editable source and exports are documented in `docs/design/README.md`.

Palette: #404040, #BFBFBF, #FFFFFF, #E6E632, #D9302E, with #F3F3F3 for a secondary surface. CSS expresses colors in OKLCH. Dark text on yellow keeps primary controls legible. Controls use fine borders, modest corners and visible keyboard focus. No offset shadows, marketing hero, generic cards, glass or decorative animation. System sans for the interface, 13–16 px controls and 24–32 px headings. The Paper wordmark uses Inter; no font software is bundled. Native macOS window, menus and folder chooser. Responsive web workspace inside WKWebView.

Use Apple Design and the detailed macOS/accessibility Human Interface Guidelines as the baseline: https://developer.apple.com/design/. Keep task flows simple, support native keyboard/menu interactions, resizable windows, visible text labels and zoom up to 250 percent. Simplify the recording view to its queue and actions. Timetable photo recognition uses Apple Vision locally and only creates editable drafts. Incomplete recognition is explicit; saving is required to apply the timetable.

The timetable is a weekly calendar, bounded by the earliest visible class start and latest class end. Days form columns; class blocks use neutral surfaces with a narrow index line. Matching recordings have a visible count. A current class may use pale yellow; state never depends on color alone. Week navigation changes recording markers. Clicking a block opens a compact edit popover; photo imports remain editable drafts. Incomplete OCR rows appear separately until their times are completed. Explanations live in hover/focus help; semester/source settings and connection documentation are collapsed by default.

The default This week screen shows the saved current-week calendar, current-time line, current/next lecture and coverage of completed classes. Audio coverage uses the union of recorded intervals clipped to class times. Access controls are contextual: recordings require a readable source, Photos is optional and unlocks only with actual macOS authorization. Class photos appear in the recording upload sheet, scoped to that lecture's recording window; there is no separate Photos tab. Native permission requests occur only after the user chooses the feature.
